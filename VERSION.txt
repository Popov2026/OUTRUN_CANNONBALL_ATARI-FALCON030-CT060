Cannonball Atari Falcon 030 / CT60 / CT63 port - v0.33 beta

Built with GCC (m68k-atari-mint-g++ 4.6.4) - see build_atari.sh / build_release.sh.

Changes since v0.32 beta:
  Sound
  - Starting a .mod (radio screen, race start) no longer breaks up the
    sound: the module used to be made ready with the sound held off (every
    sample converted to 16 bits, unused by the DSP replay, then again for
    the DSP replay). It is now made ready with the sound running, straight
    into the form its replay uses (bytes for the DSP, 16 bits only for the
    68k's mixer); the sound is only held off to swap the tunes and start
    the DSP replay (Hatari, 68060: 15 ms). Same sound, and less memory with
    the DSP replay.

Changes in v0.32 beta (since v0.31 beta):
  Sound
  - Start of the tunes no longer broken up on real machines: with mod = 1
    (the default outrun.ini) every tune start looked for Music\TRACKn.MOD on
    the disk while the sound was held off; with no such file (FM music) the
    lookup on a real hard disk or card was long enough to break up the
    sound at the start of each tune (heard on a real CT60, not in Hatari).
    The four files are now only looked up in the directory once, at
    start-up (nothing is read); a .mod that is there is read when its tune
    starts, with the sound running.
  - From a .mod tune back to an FM one (mod = 1 with only some TRACKn.MOD
    files): the DSP .mod replay kept running in the background, replaying
    silence, and the FM music stayed on the 68k. The replay now stops and
    the FM program takes the DSP back, in step with the 68k's chip (same
    sound, sample for sample). While a .mod plays, the FM program is
    stopped (it was already).

Changes in v0.31 beta (since v0.30 beta):
  Picture rate
  - fps option: a steady picture rate between the cadences (e.g. fps = 25
    or 20); replaces cadence. The game slows down if the machine cannot
    draw that many pictures.
  - Steadier automatic rate (cadence = 0): 30, 25, 20, 15, 10 or 7.5
    pictures/s; it goes down as soon as the current rate no longer fits and
    up only after about 3 s with 20 % to spare, so it no longer jumps back
    and forth.
  Speed (68030 and 68060; same pictures, pixel for pixel)
  - Sprites: zoomed sprites are drawn screen pixel by screen pixel instead
    of walking every source pixel; faster shrunk-sprite loop.
  - Background tiles: unpacked once at start-up (1 MB); rows without a
    transparent pixel are drawn two pixels at a time.
  - The screen is only written where pixels changed since the last picture.
  Together: preparing a picture in a race takes about 25 % less time
  (Hatari, 68060 at 32 MHz: ~40 ms -> ~30 ms).

Changes in v0.30 beta (since v0.27):
  Sound
  - FM on the DSP (fm_dsp = 1, default): the YM2151 FM chip is computed by a
    DSP56001 program (tools/fmdsp/fm_dsp.asm) instead of the 68k. Same sound,
    sample for sample (checked on the three music tracks in full, and in the
    game against the 68k emulation). The 68k only sends the register changes
    and reads the samples back: on a Falcon 030 the whole sound costs about
    15 ms per game step instead of 300+ ms with the FM music. The FM and PCM
    sound come out one game step (1/30 s) late.
  - Sound from a timer interrupt (sound_irq = 2, default: on with a
    68040/68060): the music keeps its tempo and has no holes even when the
    picture rate drops. Off with a 68030, which has no time to spare for it.
  - .mod music with DSPMOD 3.4 by bITmASTER of TCE (mod_dsp = 2). DSPMOD is
    written for the 68030: with a 68040/68060, and for modules with more than
    64 patterns, the modules are played by the Simplet DSP replay instead
    (as with mod_dsp = 1).
  - mod_dsp, the .mod replay (mod = 1, files in Music\):
      0 = mixed by the 68k;
      1 = played by the DSP, SoundTracker replay by Simplet / ABSTRACT
          (recommended, especially on CT60/CT63);
      2 = played by the DSP, DSPMOD 3.4 (bITmASTER of TCE), Falcon 030 only:
          with a 68040/68060, or for a module with more than 64 patterns,
          the game uses the Simplet replay (= 1). DSPMOD is not 68060-safe
          (it writes to the DSP without waiting for it and uses a 64-bit
          mulu.l, which the 68060 only emulates): it froze or slowed the
          game; and it hangs on modules with more than 64 patterns.
    While a .mod is played by the DSP, the FM sounds go back to the 68k.
  Controls
  - Joystick fixed on real CT60 hardware (enhanced ports read after a short
    settling delay; both DB9 ports read; IKBD set up through TOS).
  - Configurable joystick: joy_accel, joy_brake, joy_gear in outrun.ini
    (up, down, fire, b, c, none, combined with '+').
  - PADTEST.TOS: shows live what each joystick socket returns.
  Tools
  - ROMNAME.TOS: renames the ROM files to short 8.3 names (plain TOS) or to
    long names (FreeMiNT), recognising each ROM by its CRC32 whatever its
    current name, and sets freemint in outrun.ini to match.

Layout of this delivery:
  cannonball_src/      - full source tree, no build artifacts, no ROM data.
  cannonball_release/  - CB030.TOS / CB060.TOS, roms/, Music/, outrun.ini.
